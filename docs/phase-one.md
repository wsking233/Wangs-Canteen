# 第一阶段开发目标：统一 UI 与前端基础

状态：范围已确认，业务功能稍后确定。本阶段不根据仓库名称推断业务。

## 目标

交付可启动、可构建、可持续扩展的前端工程，以及一套来源统一的 UI 基础。通过独立的组件展示页确认视觉与交互，再进入业务开发。

## 范围与验收

| 顺序 | 交付 | 验收标准 |
| --- | --- | --- |
| 1 | React + TypeScript + Vite 工程 | 干净环境可执行 `npm ci`；`npm run dev` 启动；`npm run build` 通过 |
| 2 | Tailwind CSS v4 与主题变量 | 通过 Vite 插件编译；统一语义色、字体、圆角和间距；支持深浅主题 |
| 3 | 单一主要 UI 来源 | 使用 shadcn/ui New York；所有通用组件从 `src/components/ui` 引用；图标统一 Lucide |
| 4 | 最小组件集 | Button、Card、Input、Label、Badge、Dialog、Separator；展示主要/次要/禁用操作与标签状态 |
| 5 | 响应式展示页 | 中文界面；窄屏单列、宽屏双列；320px、768px、1440px 视口无横向溢出 |
| 6 | 可用性基础 | 输入带标签；按钮有可访问名称；键盘焦点可见；弹窗支持 Escape、焦点约束与关闭后焦点返回 |
| 7 | 工程约定 | 类型检查、代码检查、构建通过；提交依赖锁文件；记录组件来源、许可与扩展方式 |

推荐顺序为工程初始化 → 主题和组件 → 展示页 → 验证及文档。单名前端开发者可按约 3–5 个工作日规划，包含视觉确认与修正；这是估算，不是交付承诺。

## 视觉方向

暖白底色、Stone 中性色、陶土橙强调色，搭配系统中文字体。使用轻边框、少阴影、统一圆角，保持内容清晰。深色主题使用同一套语义变量，不另做组件样式。

## 复用规则

1. 优先直接使用官方组件与现有变体；页面通过组合组件实现。
2. 页面布局和响应式使用 Tailwind；颜色使用 `bg-background`、`text-muted-foreground` 等语义类。
3. 重复出现的业务组合再提取为 `src/components` 下的组件；不预先建设业务组件体系。
4. 通用交互优先使用 shadcn/ui / Radix 的现有实现，保留焦点管理和键盘交互。
5. 本阶段不叠加 Ant Design、MUI、DaisyUI 或其他样式套件。确实缺少能力时，先评估无样式工具并记录引入理由。

## 当前交付与后续边界

本次已编写工程配置、主题、七个官方基础组件、交互展示页与使用文档。自动检查和人工检查结果见 README；编写完成不等于全部验收。

业务页面、登录权限、后端、数据库、支付、订单、路由体系、全局状态管理和多语言不在本阶段实现。后续先明确服务人群和一个核心业务流程，再决定这些能力的优先级。

进入第二阶段的条件：基础检查通过、完成移动端与键盘体验检查、视觉方向确认、业务范围明确。
