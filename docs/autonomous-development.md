# 自主迭代计划

起始时间：2026-10-26 14:12 UTC。用户授权逐阶段规划、实现、验收、提交并触发 GitHub Pages 自动部署，持续最多五小时（目标截止 19:12 UTC）。每阶段控制范围，不引入额外 UI 套件、账户、后端、AI 或付费服务。

## 阶段顺序

1. **常用组合**：多食物用量组合、保存/编辑/删除、库存不足原因；兼容现有库存数据。
2. **决定一顿饭**：只从可执行组合推荐、换一个、确认实际份量、库存和用餐记录一次保存。
3. **吃过什么**：历史与撤销、重复操作保护、最近用餐对推荐的影响。
4. **本地数据安全**：JSON 备份、导入预览与确认、异常数据恢复、迁移验证。
5. **日常使用体验**：低库存与补货、导航和主题偏好、键盘/手机体验、实际使用回归。

后续阶段以已交付结果和发现的问题为依据细化，不为了耗时而堆功能。每阶段先补领域测试，执行代码检查、测试、构建及关键浏览器验收；提交 main 后追踪 Actions 部署。部署失败先修复再推进。

## 2026-10-28 产品体验迭代

- 临时用餐由“选食物 → 确认搭配 → 再确认用量”合并为一个表单：选择食物、填写实际用量后直接确认开饭；名称可留空自动生成，仍以完整快照原子保存记录与库存。
- 首页无推荐时，根据可用库存给出唯一主要入口：有食物直接“自己搭一顿”，无可用食物则去库存补货；新用户无需先创建常用搭配。
- 临时用餐默认聚焦库存搜索，少于一份的食物默认取现有数量；取消不保存，失败保留选择并展示具体错误，可重试。
- 回归补充：一步记录、小数默认量、取消与焦点返回、空库存入口，以及存储失败后重试不重复扣减。
