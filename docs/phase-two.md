# 下一步开发方向：从库存到一顿饭

## 方向与分步交付

依据 `product-vision.md`，围绕“家里有什么 → 怎么搭配 → 确认开饭”的个人使用流程推进，继续使用 React、Tailwind、shadcn/ui 和 GitHub Pages。

| 步骤 | 目标 | 验收标准 | 本次范围 |
| --- | --- | --- | --- |
| 2A 库存基础 | 先建立可信的本地库存 | 可新增、修改、补货、停用、删除；数量支持小数；刷新不丢数据 | 实现 |
| 2B 自由搭配 | 把多种食物组合成一餐 | 保存组合及各食物用量；允许同一单品参与不同组合；标出库存不足 | 已实现 |
| 2C 今天吃什么 | 推荐可执行的一顿饭并完成记录 | 只推荐库存足够的组合；换一个；确认后一次性扣减库存并创建用餐记录 | 已实现 |

先完成 2A，让用户立即记下真实库存，同时验证本地存储与数量规则；下一次直接以这些数据开发组合管理，不在本次扩展后端、账户、云同步或营养计算。

## 2A 数据和交互

- 食物字段：稳定 ID、名称、数量、单位、是否启用、可选备注。
- 数量为 0–1,000,000，最多两位小数；支持半份，补货必须大于零。补货使用整数百分单位计算，避免 `0.1 + 0.2` 精度残留。
- 数量为 0 或手动停用，均不计入“可用于搭配”；统计食物种类，不混加不同单位的数量。
- 编辑直接修正当前库存；补货增加当前数量。单位修改视为用户对整条记录的修正，不自动换算。
- 新增时保持空库存，不自动填充演示食物；首次使用提供操作引导。
- 搜索食物名称和备注，可筛选全部、可搭配、已用完或停用。
- 删除前确认，取消保留原数据。未提交表单关闭后不保存。

## 存储与错误处理

使用 `wangs-canteen.inventory.v1` 保存 `{ version: 1, foods: [...] }`，为未来结构升级保留版本号。

读取时校验数据结构、数量范围和唯一 ID；不支持或损坏的数据保持原样，不静默清空覆盖。写入成功才更新页面；浏览器拒绝存储时明确报错。多标签页通过 storage 事件同步；写入前比对上次读取内容，冲突时要求重新读取，减少旧页面覆盖新库存的风险。localStorage 不提供数据库事务，这个机制不承诺跨标签页同时写入的严格事务隔离。

数据只保存在当前浏览器设备，刷新后保留；清理站点数据会丢失，跨设备同步和导出备份留待后续实现。

## 验证

领域逻辑单测覆盖小数和边界、补货、可用状态、数据结构校验、重复 ID、并发版本冲突和存储失败；纳入 `npm run check`，由 CI 在发布前执行。

浏览器验收覆盖新增 → 补货 → 编辑 → 筛选 → 删除，以及刷新持久化、多标签页同步、存储异常保护、移动端与深浅主题。

## 2B 数据升级

沿用原存储 key，将内部结构升级为 v2，统一保存 foods 与 combinations。旧 v1 库存在读取时无损升级，首次修改时写入新结构；旧版页面遇到新版本数据时会拒绝覆盖。搭配用稳定 foodId 关联库存，同时保存用量单位，单位变更后必须重新确认，避免错误换算。删除库存不静默删除搭配，搭配显示修复提示。所有修改通过共享存储入口保存完整快照。

## 2C 用餐闭环

主页为今天吃什么，仅从库存足够且食物启用、单位一致的组合中推荐。有多个可用组合时换一个会切换到其他组合；只有一个时明确提示。确认弹窗可调整本次每项用量，不修改组合模板。记录保留食物名称和单位快照，不受后续库存改名或删除影响。

数据结构升级为 v3，记录与库存共用一次 localStorage.setItem，避免分开保存导致状态不一致。确认时重新检查库存及重复操作 ID，任意一项库存不足则拒绝整顿饭，不部分扣减。该阶段保留本地存储的乐观冲突检测，不宣称跨标签页数据库事务隔离。v1/v2 数据均能无损升级；已有记录可在用餐记录页查看。

## 用餐记录与撤销

记录支持名称/食物搜索、最近 7 天筛选，每次加载 20 条。撤销保留原记录与撤销时间，库存返还当前数量之上，重复撤销被拒绝。已删除的食物按记录中的 ID/名称/单位恢复，数量仅为本次返还用量；若现有食物单位不同则拒绝整顿饭的返还，需先纠正单位。任何一项返还超出数量上限，同样不进行部分写入。

推荐参考最近 3 顿未撤销记录，对重复组合和重叠单品降低权重，不硬性排除，仍可在常用搭配主动选择。

## 本地备份与恢复

“我的数据”可导出库存、搭配和全部历史（含撤销标记）。备份有应用来源、版本和导出时间；导入支持本应用备份以及 v1/v2/v3 原始快照，先校验格式、数量和唯一 ID，再展示食物/搭配/历史条数，经确认替换本机数据。导入不重放库存扣减与返还。文件上限 20 MB，数组数量上限食物/搭配各 10,000、记录 50,000。

损坏数据不能普通修改，但可以下载原始文本保留副本，再使用有效备份明确替换。损坏快照也参与写入冲突检查，恢复前原文已变化时拒绝覆盖。取消预览和格式校验失败不改动现有数据。所有文件处理在浏览器本地进行。

## 并发写入保护

支持 Web Locks 的浏览器中，所有本版本页面使用同名跨标签页写入锁。开始保存时捕获原快照，获取锁后再次比较，不把旧表单自动覆盖到更新后的库存。开饭、撤销、编辑、补货和备份恢复都走同一保存入口；保存成功才关闭表单。

保存期间阻止重复提交和弹窗关闭；等待锁超过 10 秒会中止，提供重试，不在稍后悄悄执行。没有 Web Locks 的旧浏览器继续使用写入前快照校验，不能承诺严格并发隔离；未升级的旧应用页面也不参与新锁，应刷新后使用。
